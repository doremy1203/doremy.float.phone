## 生活系统当前开关

- `components/life/life-engine-app.tsx`：`LIFE_PROACTIVE_MESSAGES_ENABLED = false`；
- `lib/life/life-proactive-scheduler.ts`：`LIFE_PROACTIVE_MESSAGES_ENABLED = false`；
- `lib/life/life-schedule-cloud.ts`：同步快照的 `proactiveEnabled = false`。

所以生活系统目前保留日程、场景与诊断等代码，但主动消息生成链路处于关闭状态。云端 `life-scheduler` 的日程评估代码仍在仓库中，需单独部署个人 Supabase Schema、Edge Function 和 Cron 才能执行；这与角色主动消息生成、通知投递不是同一能力。

## 自动化命令（以 package.json 为准）

| 命令 | 代码覆盖方向 |
|---|---|
| `npm run build` | 生成微信助手/个人推送产物并执行 Next.js 构建 |
| `npm run lint` | 通过仓库脚本运行 ESLint |
| `npm run test:life` | 角色 ID、生活运行时/自主规则/场景回应/输出解析/日程/通知队列/云调度等测试脚本 |
| `npm run test:photo-wall` | 照片墙贴纸尺寸与记录层相关测试 |
| `npm run test:character-id` | 角色 ID 集成测试 |
| `npm run test:widget-output` | 桌面小组件输出测试 |
| `npm run check:sdk` | 自定义 App SDK 一致性检查 |
| `npm run check:weixin` | 微信助手提示词/产物一致性检查 |
| `npm run check:push` | 个人推送部署产物一致性检查 |

这些命令的存在仅说明仓库定义了相应检查。每次发布应记录实际执行的命令、提交 SHA 和结果；不得把历史工作流通过写成当前提交的验证结果。
