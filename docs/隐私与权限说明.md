# 隐私、数据流与 Android 权限说明

> 更新日期：2026-11-01
> 本文描述本仓库当前代码的技术数据边界，帮助自部署用户作出知情选择。它不是针对所有部署方、地区或第三方服务的完整法律隐私政策；站点运营者仍需根据自己的服务、日志、联系渠道和适用法律补充政策。

## 1. 默认数据存放

- 浏览器版的数据主要保存在当前浏览器的本地存储、IndexedDB 和缓存中。
- Android 壳内的 WebView 使用独立应用沙箱，与手机 Chrome/系统浏览器的数据不互通。
- 默认自部署模式不要求连接项目维护者的中央账号或数据库。是否启用 Supabase、备份、推送等云端能力，由部署配置和用户设置决定。
- 卸载 Android App、清除浏览器站点数据或清除 App 数据，可能删除本地聊天、角色卡、生活记录、设置和未同步队列。卸载前请先使用应用内数据管理导出备份，并验证备份文件可恢复。
- Android 壳 1.0.28 起关闭系统自动备份（`allowBackup=false`）；跨设备迁移请使用应用内显式导出，并自行保管导出文件。

## 2. 哪些操作会把数据发送到外部服务

本项目不是“所有数据永远只在本机”的离线应用。用户启用或调用以下功能时，相关请求会离开设备：

| 功能 | 可能发送的数据 | 接收方 |
|---|---|---|
| AI 聊天、生活现场、角色总结 | 本轮输入、为生成上下文选取的角色设定、相关历史/记忆、工具参数 | 用户在设置中配置的 LLM 服务商 |
| AI 生图、参考图、图床 | 提示词、用户选中的角色参考图/上传图片、生成结果 | 配置的生图服务、图床或代理服务 |
| 一起看、视频理解、转写 | 视频 URL、用户选择的截图/关键帧、字幕/转写文本或用户主动提供的视频文件 | 配置的视频解析、视觉理解、转写服务或目标视频平台 |
| 云端备份、同步、推送和后台日程 | 用户选择同步的备份数据、账号/设备标识、排期与推送所需字段 | 用户自行配置的 Supabase 项目；若部署者预置了项目，则由该部署者配置的项目接收 |
| 邮件自动现实桥 | 用户配置的收件信息、消息内容和验证信息 | 用户配置的邮件服务商（例如 Resend） |
| 站点访问与资源下载 | 正常 HTTP 请求元数据，例如 IP、时间、请求路径和 User-Agent | 网站托管商、CDN、反向代理或用户自建服务器 |

第三方服务的数据保留、地区、训练使用、日志和删除规则由对应服务商的条款决定。本项目无法替用户控制第三方服务商的留存策略。不要把 API Key、Cookie、Authorization 头或私密聊天内容提交到公开 issue。

## 3. 本地诊断记录

- 生活系统诊断记录默认保存在本机，最多保留最近 300 条，不会自动上传。
- Android 原生崩溃摘要、WebView 控制台诊断和运行诊断报告保存在本机；部分日志只在当前进程生命周期内保留。
- 用户主动导出的 JSON/诊断报告可能包含设备型号、系统/WebView 版本、场景 ID、角色标识、错误详情和时间戳。公开分享前请人工检查并脱敏。
- 诊断日志不是完整系统 Logcat，也不能证明后台任务或通知已在所有机型上运行成功。

## 4. Android 权限与原生能力

权限声明不等于已经获得授权。危险权限、特殊访问权限和系统能力通常还需要用户在系统弹窗或设置页明确授予；拒绝可选权限通常只会让对应增强功能不可用，不应影响基础网页聊天。

| 权限 / 系统能力 | 用途 | 可选性与注意事项 |
|---|---|---|
| 网络访问、网络状态 | 加载站点、访问用户配置的 API、Supabase 和本地解析服务 | 网络功能必需；外部请求按用户配置发出 |
| 通知、前台服务、开机接收 | 原生推送长连接、通知展示、用户启用的后台任务与重启恢复 | 通知可关闭；后台存活仍受 Android/厂商电池策略影响 |
| 摄像头、麦克风及对应前台服务 | 用户主动使用视频/语音通话或 WebView 媒体采集 | 不使用相关功能时可拒绝；系统会在使用时授权 |
| 悬浮窗、振动、全屏通知 | 通话浮窗、来电提醒和交互 | 需要用户授权或受 Android 版本限制；不是普通网页权限 |
| 精确/后台位置、活动识别 | 用户启用的位置感知、到达/离开与活动状态能力 | 属于敏感能力；建议只在确实需要时开启，可随时在系统设置撤销 |
| 使用情况访问、已安装应用可见性、无障碍服务 | 用户启用“前台应用/停留时长”感知时，读取当前前台应用包名与停留时长 | 不等同于读取其他 App 的屏幕内容；无障碍服务必须由用户在系统设置主动开启 |
| 日历读取/写入 | 用户启用系统日历联动时读取日程或创建事件 | 可拒绝；不会因为声明权限就自动读取日历 |
| Health Connect 睡眠读取 | 用户启用健康联动后读取获授权的睡眠记录 | 通过 Health Connect 单独授权；拒绝不影响其他功能 |
| 通知使用权（Notification Listener） | 获取活动媒体会话，以控制播放/暂停并读取播放状态 | 当前服务不读取通知正文；用户可在系统设置撤销 |
| 蓝牙连接 | 通话时使用已配对蓝牙音频设备 | 不声明附近设备扫描权限 |
| 精确闹钟、唤醒锁、电池优化设置、系统设置/勿扰策略 | 定时提醒、后台连接、用户主动配置的系统动作 | 部分为特殊访问权限；仅在用户启用相应功能时使用 |
| 旧版 Android 写入公共下载目录 | Android 9 及以下保存用户主动导出的文件 | 仅声明到 API 28；Android 10+ 使用 MediaStore |

当前 Manifest 已移除未被现有原生实现使用的短信、通话记录、通讯录、整库媒体读取、身体传感器扫描、蓝牙扫描、NFC 和状态栏展开权限。文件导入通过 Android 系统文件选择器授予单个 URI，不需要读取整个媒体库。

### Google Play 分发提醒

本项目面向 GitHub 自部署与用户自建 APK。QUERY_ALL_PACKAGES、后台位置、无障碍服务、精确闹钟、全屏通知、电池优化豁免和特殊用途前台服务等能力，在 Google Play 上可能受到严格政策限制，需要逐项证明核心用途、填写权限声明并通过审核。GitHub 可下载 APK 不等于已满足 Google Play 上架政策。

## 5. 用户如何控制与删除

1. 在 Android 设置中可以逐项撤销通知、位置、摄像头、麦克风、无障碍、通知使用权、悬浮窗、使用情况访问和 Health Connect 授权。
2. 不启用云端备份、推送或第三方 API 时，不会因为仅仅安装项目就自动把本地聊天历史同步到某个项目维护者的 Supabase。
3. 导出诊断、聊天备份或截图前，请检查文件内容；发给维护者时只提供必要的脱敏信息。
4. 删除本机数据请使用应用内数据管理或系统应用数据管理。外部 LLM、图床、邮件、Supabase 等服务上的数据，需要按相应服务商的删除流程处理。

## 6. 自部署密钥安全

- NEXT_PUBLIC_* 会进入客户端构建产物，只能存放公开 URL、anon/publishable key 等公开值。
- Supabase service role、邮件 API Key、第三方私钥、APK keystore 和密码只能放在服务端环境变量或 GitHub Actions Secrets，绝不能写进客户端代码、README、截图或公开仓库。
- .env.example 只提供空值示例。部署者应复制到本地 .env.local，并确认 .env.local、keystore 和个人备份不在 Git 跟踪范围内。
- 如果怀疑密钥曾经提交到 Git 历史，应立即在对应服务商轮换，而不只是删除当前文件。

## 7. 适用范围

不同部署者可以自行配置托管平台、Supabase 项目、模型服务和第三方代理，因此实际数据流会因部署而不同。使用者应同时阅读 README、部署文档和所选第三方服务商的条款；部署者应在自己的站点提供准确的隐私政策和联系渠道。
