## 当前发布定位

**定位：可供开发者自行部署和测试的公开代码仓库；不能标记为已经完成全平台验收的稳定发行版。**

原因不是断言功能不可用，而是以下事项需要不同证据：
1. 源码中存在实现；
2. 自动化脚本执行成功；
3. 用户自己的第三方云服务已部署；
4. 真实 Android 设备端到端运行成功。

这四种状态不能互相替代。

## 已知限制与发布前必须说明的事项

### 生活系统
- 当前客户端主动消息开关固定为关闭；不得宣传角色后台主动消息当前可用。
- 云端日程评估需用户自己的 Supabase Schema、Edge Function、Cron 和密钥。
- 日程评估、AI 消息生成和设备通知送达是不同链路。

### 视频能力
- 站内解析、本地解析服务、转写服务和 AI 视频理解互相独立。
- 平台登录态、Cookies、风控、地区、DRM、网络和接口变动可能导致失败。
- 不得宣传为所有短视频平台均可解析或下载。

### Android
- APK 安装成功不等于通知、后台连接、通话浮窗、小组件、截屏或设备动作都可用。
- 特殊权限需要用户授权；后台执行受系统版本和厂商电源管理影响。
- 小组件多实例隔离、跨应用浮窗、锁屏通知和长时间后台推送需要目标设备实测。

### 数据与隐私
- 浏览器与 Android WebView 的本地存储不互通。
- 用户启用模型、图床、视频解析、Supabase、邮件等外部服务时，相关数据会发送到对应服务。
- 发布者必须提供与自身部署配置相符的隐私说明，不能直接把仓库技术说明当成完整法律隐私政策。

## 自动化与设备验收记录

不要在这里永久写死旧工作流 run 的成功状态。每次发布请记录：
- 目标 commit SHA；
- Web 构建与 TypeScript 检查结果；
- 相关专项测试实际执行结果；
- Android debug/release 构建结果及签名验证；
- 个人云 Schema / Edge Function / Cron 版本；
- 真机型号、Android/WebView 版本、APK versionCode 和逐项测试结果。

历史工作流记录仅证明对应提交和对应 job 当时的执行结果，不自动覆盖当前提交。

## 发布门禁清单

- [ ] README 与当前源码入口一致。
- [ ] `.env.example` 不包含真实密钥。
- [ ] `npm run build` 在目标提交通过。
- [ ] 与本次改动相关的测试脚本在目标提交通过。
- [ ] Android debug APK 构建成功；如发布 signed release，完成签名验证。
- [ ] APK 的 SITE_URL 指向预期站点，versionCode 高于已发布版本。
- [ ] 个人 Supabase 部署版本与网页代码兼容。
- [ ] 备份导出与恢复实际验证。
- [ ] 至少在目标设备上验证登录、聊天、通知、通话浮窗和主要新增功能。
- [ ] 文档明确列出未配置、未验证或受第三方平台限制的能力。

在没有逐项证据前，发布说明应使用“代码包含”“需配置”“待设备验证”等表述，不应使用“全部实现”“全机型兼容”“后台永久运行”等承诺。
