## 一、这次到底发生了什么

本次同步不是单纯更新图标，而是将一批网页端功能、Android 壳原生能力、离线推送链路、桌面小组件、现实桥与感知能力，以及配套说明文档合并到分享仓库的 `main`。

合并后又补进了 Android 壳图标资源。随后 GitHub Actions 的 APK 构建已成功；这说明该次构建流程通过，但不代表每一项设备能力都已经实机验证。

## 二、主要改动总览

### 1. Android 壳与原生桥接

涉及 `android-shell/` 下的 Kotlin、Manifest、资源与构建配置。

主要内容包括：

- **通话浮窗**：网页通话状态与原生浮窗之间的桥接、浮窗服务和控制逻辑。
- **设备动作桥**：为网页功能提供调用系统能力的原生入口。
- **感知桥**：为应用使用状态、位置、日历、健康睡眠等能力提供壳侧接口。
- **截屏与主动查岗**：截屏入口、预览确认相关服务与桥接。
- **通知与通知栏回复**：原生通知、通知点击后的会话跳转，以及通知栏直接回复接收。
- **桌面小组件**：接收网页生成的内容、渲染为图片并显示在 Android 桌面。
- **启动与权限声明**：补充对应的服务、广播接收器、权限和系统意图声明。
- **应用图标**：更新 `android-shell/app/src/main/res/drawable/appicon.png`，Manifest 已引用该资源。

重要提醒：Manifest 声明权限不等于系统已经授予权限。位置、麦克风、摄像头、通知、悬浮窗、使用情况访问、通知使用权、健康数据等能力，仍可能需要用户在手机系统设置中单独授权；不同 Android 版本和厂商系统的表现也可能不同。

### 2. 通话体验

主要涉及 `components/chat/`、`lib/` 中的通话模块，以及 Android 壳的浮窗服务。

改动覆盖：

- 将通话状态提升到全局层，使通话界面可以最小化并在其他页面之间保持。
- 语音、视频、群聊通话与原生浮窗的状态联动。
- 通话中角色自动搭话的控制。
- 忙碌时的回复排队，避免消息因角色正在说话或思考而被静默丢弃。
- 通话浮窗的回复条、外观配色与诊断信息。
- 通话消息的折叠展示与边界标记。
- 通话合成语音的留档，以及字幕的重听、编辑、删除和重新生成操作。
- 通话期间对部分离线主动消息排期进行抑制或撤销，减少通话中出现不合时宜的通知。
- 主动来电相关提示与后续回应链路。

## 三、Android APK 构建与签名

相关文件：

- `.github/workflows/android-shell.yml`
- `android-shell/build.gradle`
- `android-shell/app/build.gradle`

当前工作流可构建 Debug 与 Release APK，并上传为 Actions 构建产物。签名通过仓库 Secrets 注入，相关教程已写在 Android 壳 README 中。

请区分以下状态：

- **Actions 绿色成功**：该次工作流完成，不等于每项功能都通过实机测试。
- **Debug APK**：未配置固定签名时会使用 CI 环境的临时 Debug 密钥，不适合作为长期稳定的升级签名。
- **Release APK**：没有正确配置签名时，不能当作可直接发布和持续覆盖安装的正式包。
- **个人签名密钥**：每个人应自己创建并保管；密钥丢失或更换会影响后续覆盖安装。不要把密钥库或密码提交到仓库。

具体配置步骤请以 `android-shell/README.md` 为准。

## 四、合并后还需要单独确认什么

建议按下面顺序验收，而不是只看构建是否成功：

1. **网页端**：确认站点部署到了预期版本，关键页面能正常打开。
2. **APK**：从对应的 Actions 运行下载正确的构建产物，安装并确认应用图标、启动和站点地址。
3. **权限**：在目标手机上逐项检查通知、后台运行、悬浮窗、麦克风、摄像头、位置、日历、使用情况访问等权限。
4. **通话**：测试最小化、切换页面、原生浮窗、忙时排队、挂断和通话记录。
5. **推送**：分别测试前台、后台、杀进程或重启后的行为，并查看自检/诊断结果。
6. **桌面小组件**：确认能添加到桌面、推送内容成功、桌面图片实际更新。
7. **现实桥与感知**：先从单条规则和单项权限开始，确认触发条件、执行结果和失败原因，再扩大配置。
8. **云端配置**：单独确认 Netlify 环境变量、Supabase 项目、Functions 部署和数据库配置。它们不会因为 GitHub 合并代码而自动复制到另一个环境。

## 六、2026-10-24 后续更新：视频解析内置化与三大 App 修复

> 本节是后续增量，不覆盖前面的历史记录。当前对应提交：`151528895b8c15761e814a51e89942d4be98e84a`。

### 一起看

- 新增网页端内置解析链路：`lib/watch-resolver.ts` 与 `/api/watch-resolver/*`，支持解析、下载和同源缓存播放；缓存具备 LRU 容量管理及 HTTP Range 断点读取。
- 新增 `/api/resolve-short-link`，将 B 站 `b23.tv` 短链接换算为标准视频标识；播放入口按内置解析、外部解析服务、官方嵌入的顺序回退。
- 观看记录与缓存关联，支持继续观看、删除缓存及记忆播放位置；下载任务增加 30 分钟竞态保护，避免切换视频后迟到的结果覆盖当前视频。
- 同源缓存允许截帧；「标记重点」改为直接针对当前播放时间点反馈。
- 抖音等需要登录态的平台可在设置中配置用户自己的 Cookies。平台风控、登录限制、地区限制及版权/DRM 限制仍可能导致失败。

### 生活系统

- 修复时钟控制区无法访问的问题，时间流速、时间模式与 +1 小时操作现在有对应实现。
- 沉浸场景中的提示改为固定浮层，降低提示被内容遮挡或看不到的情况。
- 行程编辑新增地点时会写入地点库，并修复中文 slug 正则转义问题。

### 照片墙

- 使用会话级缩略图处理，减少重复解码大图带来的卡顿。
- 整墙导出按画布世界分辨率输出（起始 2400，最大 6400），并让背景铺放与导出保持一致。
- 「全部记忆」加入底部导航；批量上传按当前视野放置；每日生成尊重角色选择，失败不自动重试。
- 修复壳缩放比例不为 1 时双指缩放/涂鸦坐标漂移的计算问题。

### 桌面小组件与通话统计

- 「在桌面留句话」工具支持通过 `profileId` 指定组件实例，并为各实例分别存储数据；这修复的是代码层的实例隔离，仍需在 Android 启动器上实测添加两个不同实例。
- 通话统计 App `call.stats 2.1.0` 已作为内置 App 接入 `CustomAppRunner`，通过 AiPhone 桥读取统计、日历、通话回看、原音复听与 AI 总结能力。

### 工程与文档

- 生产构建重新启用类型检查（`ignoreBuildErrors: false`）。
- 清理无效弹幕组件、横屏残留样式、过期解析状态及照片墙无用导出。
- 本地视频转写服务默认端口调整为 `8766)，避免与视频解析服务冲突。
- 新增 `scripts/sync-to-public.mjs`，用于实验仓库到公开仓库的同步。

以上为提交内容摘要，不代表全部完成真机验收。逐项验证状态见 [开发进度与验证清单](./开发进度与验证清单.md)。
